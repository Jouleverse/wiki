### 二、 教链 J-25 发言纪要

教链在本次会议中主要围绕**统计数据的可追溯性与存储方案**展开了系统性的分析，并提出了具体改进建议。核心内容如下：

#### 1. 问题定性

教链首先厘清了微尘所提问题的本质：并非单纯的隐私或飞书链接稳定性问题，而是**数据可追溯性**问题。即当最终统计表中的数据（如某人的工作量小时数）受到质疑时，应当能够从最终表格一路反向追溯至最原始的数据留痕（如 GitHub 的 commit 或 PR），以确保数据的可验证性。

#### 2. 现状分析

- 当前使用飞书表格作为**中间数据载体**，用于人工协作汇总原始数据，再生成 GitHub 上的最终定稿统计表。
- 飞书表格作为中间跳转节点存在**不稳定性**（依赖个人账号，可能失效），可能导致未来的追溯链路中断。
- 焦耳通讯的定位是**对外宣传窗口**，不适合承载详细的运营数据表格，仅适合发布公告快讯并附链接。

#### 3. 解决方案建议

教链提出一套具体可行方案：

1. **在 GitHub 上创建独立的中间数据表文档**：在最终统计表（如 `powh202609.md`）旁边，新建一个名为 `powh202609-raw.md`（或类似命名）的 Markdown 文件。
2. **该文件内容**：汇总各项工作的原始数据来源、计算过程（如“2小时×7个月=14小时”）、以及进一步追溯的链接（如发放记录、上报记录等），相当于“参考文献”式的数据溯源索引。
3. **最终统计表中添加反向链接**：指向该原始数据汇总文件，供有疑问时查阅。

#### 4. 方案优势

- **持久可靠**：与最终统计表同在 GitHub 上，不存在飞书账号失效的问题。
- **无隐私顾虑**：无需暴露个人飞书对话或账号信息。
- **工作流统一**：整个流程（包括 PR 审查、合并）均在 GitHub 完成，便于 AI 介入。
- **为自动化奠基**：只要制定好统计规范、模板，未来可让 AI 直接从原始数据源抓取并生成该中间表及最终统计表，实现全自动化。

#### 5. 结论与后续

教链建议可立即尝试该方案，比如可由 Bataroc 尝试制定模板并用 AI 测试生成。
